# The GM gate, reveals and the player view

Date: 2026-10-03
Status: implemented 2026-10-03

## Why

A campaign vault is full of things the players must not see yet. Phase 3 needs a way to mark
them in the files — readable in any other editor — and a view of the vault as the table knows it,
at any session. This sub-project is the security-relevant one: everything here defaults to deny.

## Decisions taken with the maintainer

- Two lenses. The app as it is, the **GM lens**, shows everything, gated text marked. The **player
  view** is a separate read-only route with its own API routes that can only reach the public side
  of the index.
- The player view shows only notes inside the campaign that the party has met by the chosen
  session, the session notes up to it, and notes marked `public: true`. Nothing else exists there.
- No frontmatter in the player view; `%%…%%` can never be revealed.
- Without a login (Phase 4) the player view is honest about being a view, not a lock.

## What is gated

- A **GM callout**: a blockquote whose first line is `[!gm]` (any case, optional `-` or `+`,
  optional title), at any depth — inside a list, inside another quote. The whole blockquote is
  gated. `revealed: N` anywhere in its first line (`> [!gm] revealed: 12`) makes it public from
  session N on; any other or no `revealed` keeps it gated for good.
- A **comment**: `%%…%%`, inline or across lines, outside code. Always gated. An `%%` that is never
  closed gates everything after it.
- The **frontmatter** block: never shown in the player view.
- Detection uses the Markdown parser, so `%%` inside code spans and fences is text, and a `[!gm]`
  inside a fence is not a callout.

`publicMarkdown(markdown, session)` in core returns the note without everything that is not public
at that session; gated callouts are removed with their whole lines, comments as spans. It is the
one function both the indexer and the player view use.

## The index

- `notes` gains `public_title`, `public_body` and `gates` (JSON: each gate's kind, line range and
  reveal session). `public_body` is the note's text at session 0: every GM callout removed,
  revealed or not, so a block marked `revealed: 99` is not findable before session 99. The public
  title is the first heading of the public text, else the file name — never the frontmatter
  `title`.
- `notes_public_fts` indexes `public_title` and `public_body` only.
- The schema version rises; the index rebuilds once.

## Who has met what

- A **session note** is a note inside the campaign with `type: session` and an integer
  `session:`. Its number orders the sessions; the player view's slider runs over them.
- A note is **met** at session N when a session note numbered ≤ N links to it from a line that is
  public at N. Notes outside the campaign are never visible, whatever links to them.
- **Visible at N**: session notes numbered ≤ N, notes met by N, and campaign notes with
  `public: true`.

## The player view API

`/api/v/{vault}/table/…`, registered with a `PublicIndex` that exposes only public columns and the
visibility rules — never the full index:

- `GET sessions` → `{ campaign: boolean, sessions: number[] }`.
- `GET notes?session=N` → the visible notes, `{ path, title }` with the public title.
- `GET notes/{path}?session=N` → `{ path, title, markdown }`, the public Markdown at N. A note that
  is not visible answers exactly like one that does not exist (404, same message).
- `GET search?q=&session=N` → hits from `notes_public_fts`, restricted to visible notes, with
  snippets cut from the public text.
- `session` defaults to the latest session; a number above it is the latest.

## The web app

- GM lens: `[!gm]` is a callout kind of its own — the rust colour and the word "GM" ("SL") — and
  `revealed: 12` stays visible as its title. Everything else is unchanged.
- Player view at `/v/<id>/table` and `/v/<id>/table/<note>`: no sidebar tree, no editor, no
  frontmatter; a session slider, the list of visible notes, a search, and the note rendered from
  the public Markdown. A link to a note that is not visible is plain text; an embed of one is its
  placeholder. A banner says: player view — not locked; whoever has the address can open the GM
  view; the lock comes in Phase 4.
- A "Player view" link in the header (GM lens) opens it.

## Not part of this sub-project

Who was told (named reveals), the capture bar, the acquaintance colouring of the field, a lock,
hiding vault assets (an image embedded only in a GM block can still be fetched by its address —
Phase 4).

## Tests

- Unit (core): every gate spelling and nesting, code spans and fences, an unclosed `%%`, the
  reveal boundary N−1/N, frontmatter removal, public title.
- Unit (server): the leak test — a vault with a distinct `SECRET-…` marker in every gated form
  (callout, nested callout, comment, unclosed comment, frontmatter, a revealed block before its
  session, an unmet note, a note outside the campaign); every `table` route for every session; no
  response contains a marker it may not. Visibility and met rules. 404 parity.
- Playwright: the player view hides a GM block; the slider shows it from its session on; a link
  to an unmet note is plain text; the GM lens shows the block marked.
