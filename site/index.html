Networked knowledge, kept in plain Markdown files.

Rhizom is a self-hostable, open-source tool for networked knowledge. It will read a folder of Markdown files, index the links between them and draw the vault as a field of bubbles: notes as circles, folders and tags as colour, links as connections. Every vault will double as a wiki.

View on GitHub Read the roadmap

Early development. Nothing to install yet.

Files first

  • The files are the source of truth. A vault is a folder of Markdown files. It stays readable with any editor, with or without Rhizom.
  • The index is derived. SQLite will hold only what can be rebuilt from the files: links, tags, frontmatter, full text. Delete it and it comes back.
  • An Obsidian vault will open as it is. Rhizom will read a folder of .md files with [[wikilinks]] directly, with no import and no conversion.

What Rhizom will do

Editor
Planned for Phase 1, expanded in Phase 2
CodeMirror 6 with live preview, [[ autocomplete across the whole vault, and links that create the note when it does not exist yet.
Bubble graph
Planned for Phase 1
Bubble size follows link degree, clusters take their colour from folder or tag, a local graph shows the neighbourhood of one note, and any view exports as SVG or PNG.
Wiki mode
Planned for Phase 1
A read-only view of the whole vault with rendered links, navigation and search.
Self-hosting
Planned for Phase 1, desktop installers in Phase 5
One Docker command, or a native process on a machine you control. Installers for Windows, macOS and Linux come later.

Who it is for

  • The self-hosting community. It will run as one container or one process on your own hardware, with no third-party account and nothing that phones home.
  • Researchers. Sources, arguments and open questions as linked notes, with the shape of a topic visible at a glance.
  • Authors. Characters, places and plot threads as a map that grows alongside the manuscript.
  • Game masters. A campaign as a vault. A per-vault D&D mode is planned for Phase 3: NPC stat blocks, typed relationships, dice, and sections only the GM can see.
